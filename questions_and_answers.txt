WORLD 1: PYTHON

[TIER 1 — FOUNDATIONS]

Topic 1: Variables & Data Types
- Question: How does Python determine the data type of a variable, and what is the difference between an integer and a float?
- Key Concepts: Dynamic typing; type inference; integers are whole numbers; floats have decimal points.
- Model Answer: Python uses dynamic typing, meaning it automatically infers a variable's data type at runtime based on the value assigned to it without requiring explicit type declarations. An integer (int) represents a whole number with no fraction (like 42 or -5), whereas a floating-point number (float) represents real numbers containing a decimal point (like 3.14 or -0.5).

Topic 2: Operators & Expressions
- Question: What is the difference between the / operator and the // operator in Python?
- Key Concepts: True division returns float; floor division truncates fraction to integer.
- Model Answer: The single slash / performs standard float division and always returns a floating-point number (for example, 7 / 2 evaluates to 3.5). The double slash // performs floor division (integer division), which divides the numbers and rounds down to the nearest integer, discarding any fractional remainder (so 7 // 2 evaluates to 3).

Topic 3: Input / Output
- Question: What data type does the input() function return by default, and how do you convert it to a number?
- Key Concepts: input() always returns str; conversion with int() or float().
- Model Answer: The input() function always captures and returns user keystrokes as a string (str), even if the user typed numbers. To perform arithmetic with the user's input, you must explicitly convert (typecast) the string to a numeric type using int(user_input) for whole numbers or float(user_input) for decimals.

Topic 4: Conditional Statements (if / elif / else)
- Question: How does Python use indentation to define blocks of code inside an if/elif/else statement?
- Key Concepts: Whitespace indentation replaces curly braces; colon : starts block; uniform spacing.
- Model Answer: Unlike languages that use curly braces, Python relies on whitespace indentation (typically 4 spaces) to define code blocks. A conditional statement ends with a colon (:), and all subsequent lines indented underneath that statement belong to its execution block. When indentation returns to the previous level, the block ends.

Topic 5: Loops (for, while)
- Question: When would you choose to use a for loop with range() instead of a while loop in Python?
- Key Concepts: for loop for known count/iteration over sequence; while loop for indeterminate condition.
- Model Answer: You choose a for loop with range() when you know in advance how many times you need to repeat an action, or when iterating over a fixed sequence of numbers or collection items. You choose a while loop when repetition depends on an ongoing boolean condition that changes dynamically, such as waiting for valid user input or a game-over flag.

[TIER 2 — CORE]

Topic 6: Functions & Parameters
- Question: How do default parameter values work in Python functions, and why must they come after non-default parameters?
- Key Concepts: Optional arguments; default values assigned with =; syntax rules prevent ambiguity.
- Model Answer: Default parameters allow you to provide a fallback value in the function definition (e.g. def greet(name, greeting="Hello")), so callers can omit that argument. They must follow all positional parameters because Python assigns arguments from left to right; placing a default parameter before a required parameter would make it ambiguous which argument the caller intended to supply.

Topic 7: Lists & Tuples
- Question: What is the primary difference between a Python list and a tuple, and when should you choose a tuple?
- Key Concepts: Lists are mutable []; tuples are immutable (); tuples for fixed records and dictionary keys.
- Model Answer: The primary difference is mutability: lists are mutable and can have items added, removed, or changed in-place, whereas tuples are immutable and cannot be altered once created. You should choose a tuple when storing fixed, read-only data (like coordinate pairs (x, y) or database records) to prevent accidental modification and optimize memory usage.

Topic 8: Dictionaries & Sets
- Question: How does a Python dictionary store data using key-value pairs, and why can sets not contain duplicate values?
- Key Concepts: Dictionaries map unique hashable keys to values; sets enforce uniqueness via hashing.
- Model Answer: A dictionary stores associations between unique keys and corresponding values in curly braces {key: value}, allowing instant lookup by key. A set is an unordered collection of distinct elements that relies on hashing; when a duplicate item is added to a set, its hash collides with the existing element, automatically discarding the duplicate.

Topic 9: String Manipulation
- Question: How does string slicing with [start:stop:step] work in Python?
- Key Concepts: Zero-indexed slicing; stop index is exclusive; step controls stride and reversal.
- Model Answer: Slicing extracts a substring using the syntax text[start:stop:step]. The "start" index is the beginning position (inclusive), "stop" is where extraction ends (exclusive), and "step" determines the increment between characters. For example, text[0:5] extracts the first 5 characters, while text[::-1] reverses the entire string using a negative step.

Topic 10: File Handling
- Question: Why is it best practice to use the "with open(...)" statement when reading or writing files in Python?
- Key Concepts: Context manager; automatic resource cleanup; guarantees closure even during exceptions.
- Model Answer: Using "with open(...) as file:" employs a context manager that automatically closes the file when the block completes, even if an unexpected runtime error or exception occurs inside the block. This prevents file corruption, memory leaks, and locked file handles without needing manual close() calls.

Topic 11: Exception Handling
- Question: What is the purpose of the try-except block in Python, and when does the finally block execute?
- Key Concepts: Catching errors without crashing; except handles specific error; finally always runs.
- Model Answer: A try-except block allows you to catch and handle anticipated runtime errors (like FileNotFoundError or ValueError) gracefully, preventing the entire Python program from crashing. The "finally" block is guaranteed to execute unconditionally after the try and except blocks finish, making it ideal for cleanup tasks like releasing network sockets.

[TIER 3 — ADVANCED]

Topic 12: OOP — Classes & Objects
- Question: What is the purpose of the __init__ method in a Python class, and what does the "self" parameter represent?
- Key Concepts: Constructor method; self refers to current object instance; attribute initialization.
- Model Answer: The __init__ method is Python's constructor that is automatically invoked whenever a new instance of a class is instantiated, setting up initial object state. The "self" parameter explicitly represents the specific instance of the object being created, allowing attributes (like self.name) and methods to be bound to that individual instance.

Topic 13: OOP — Inheritance & Polymorphism
- Question: How does a child class inherit methods from a parent class in Python, and how do you call the parent method using super()?
- Key Concepts: Subclassing with class Child(Parent):; method overriding; super() calls base implementation.
- Model Answer: A child class inherits all attributes and methods of a parent class by passing the parent class name in parentheses during declaration: class Child(Parent). If the child overrides a parent method but still wants to execute the parent's logic, it calls super().method_name(), seamlessly invoking the base class implementation.

Topic 14: Modules & Packages
- Question: What is the difference between a Python module and a package, and what does __name__ == "__main__" do?
- Key Concepts: Module is single .py file; package is directory with __init__.py; script entry point check.
- Model Answer: A module is a single Python file containing functions and classes, whereas a package is a directory containing multiple modules along with an __init__.py file. The condition if __name__ == "__main__": checks whether the script is being executed directly from the terminal (where __name__ is set to "__main__") rather than being imported into another module.

Topic 15: List/Dict Comprehensions
- Question: How does a list comprehension create a new list compared to a standard for loop, and how can you add a condition to it?
- Key Concepts: Concise syntax [expr for item in iterable if condition]; expressive and performant.
- Model Answer: A list comprehension constructs a new list in a single readable line using the syntax [expression for item in iterable], which is faster and cleaner than initializing an empty list and appending in a multi-line loop. You append a filter condition at the end (e.g. [x * 2 for x in numbers if x > 0]) so only items matching the condition are processed.

Topic 16: Decorators & Generators
- Question: What does the "yield" keyword do inside a Python generator function, and how does it save memory compared to returning a full list?
- Key Concepts: Lazy evaluation; yields one value at a time; execution paused until next() called.
- Model Answer: The "yield" keyword temporarily pauses function execution and returns a value to the caller, saving its current local state. When the next item is requested, execution resumes right where it left off. This saves massive amounts of memory because values are generated lazily one at a time on demand, rather than generating and storing millions of items in RAM all at once.

WORLD 2: C#
================================================================================

[TIER 1 — FOUNDATIONS]

Topic 1: Variables & Data Types
- Question: What does it mean that C# is a statically-typed language, and what is the difference between value types and reference types?
- Key Concepts: Types checked at compile-time; value types hold data on stack; reference types point to heap.
- Model Answer: Being statically typed means every variable's type (like int, string, or bool) is known and verified at compile time, catching type errors before code runs. Value types (like int, bool, structs) store their data directly in stack memory, whereas reference types (like string, object, classes) store a pointer that references data residing in heap memory.

Topic 2: Operators & Expressions
- Question: How does the modulus operator (%) work in C#, and how can you use it to check if a number is even or odd?
- Key Concepts: Modulus returns integer remainder; number % 2 == 0 indicates even.
- Model Answer: The modulus operator (%) divides two integers and returns the remainder. To check if a number is even or odd, you evaluate number % 2: if the remainder is 0 (number % 2 == 0), the number is even; if the remainder is 1 or -1, the number is odd.

Topic 3: Console I/O
- Question: Why must you use int.Parse() or Convert.ToInt32() when reading user input from Console.ReadLine() in C#?
- Key Concepts: Console.ReadLine returns string; parsing converts textual representation to integer.
- Model Answer: Console.ReadLine() reads user input from the terminal strictly as a string. Because C# is strongly typed, you cannot perform mathematical calculations or assign text directly to an int variable without converting it. Methods like int.Parse() or int.TryParse() convert the numeric string characters into a true 32-bit integer.

Topic 4: Conditional Statements
- Question: When is it cleaner to use a switch statement instead of multiple if-else if branches in C#?
- Key Concepts: Matching discrete values of single variable; readability; switch expressions in modern C#.
- Model Answer: A switch statement is cleaner when you are evaluating a single variable against multiple distinct constant values (such as an enum, status code, or menu choice). It groups possible outcomes into organized "case" branches, which is significantly more readable and maintainable than chaining half a dozen if-else if comparisons.

Topic 5: Loops
- Question: How does a foreach loop differ from a standard for loop when iterating over an array in C#?
- Key Concepts: foreach iterates over IEnumerable without index tracking; for loop uses numeric index counter.
- Model Answer: A foreach loop automatically iterates through every element in an array or collection using an iterator without requiring manual index variables or boundary checks, making it clean and safe from off-by-one errors. A standard for loop uses an explicit index counter (i), which is necessary when you need to know the index position or modify array elements in place.

[TIER 2 — CORE]

Topic 6: Methods & Parameters
- Question: What does the "void" return type mean on a C# method, and what is the difference between passing by value versus using the "ref" keyword?
- Key Concepts: void means no value returned; value passing copies data; ref passes memory reference.
- Model Answer: The "void" keyword indicates that a method performs an action but returns no value to the caller. By default, C# passes arguments by value, meaning the method receives a copy of the variable. Using the "ref" keyword passes a direct reference to the original variable's memory address, allowing the method to modify the caller's variable permanently.

Topic 7: Arrays & Collections (List)
- Question: What is the main advantage of using a List<T> over a standard fixed-size array in C#?
- Key Concepts: Dynamic resizing; generics provide type safety; rich LINQ and helper methods.
- Model Answer: A standard C# array has a fixed size determined at creation that cannot grow or shrink. A List<T> is a generic collection that dynamically resizes itself as you add or remove elements using methods like .Add() and .Remove(), offering flexibility along with complete type safety.

Topic 8: Strings
- Question: Why are C# strings immutable, and how does string interpolation ($"Hello {name}") simplify string formatting?
- Key Concepts: Immutability creates new string on modification; string interpolation embeds expressions directly.
- Model Answer: C# strings are immutable for thread safety, caching, and security; any modification actually allocates a new string in memory. String interpolation prefixing a string with $ allows developers to embed variables and expressions directly inside curly braces within the string literal ($"Hello {name}"), making code far cleaner than calling string.Format() or concatenation (+).

Topic 9: Exception Handling
- Question: Why should you catch specific exceptions (like FormatException) instead of only catching the general Exception class in C#?
- Key Concepts: Targeted error recovery; avoids masking unexpected bugs; defensive programming.
- Model Answer: Catching specific exceptions (such as FormatException or FileNotFoundException) allows your program to handle known errors with appropriate recovery logic while letting unexpected, critical bugs bubble up to be diagnosed. Catching the generic Exception class blindly can mask serious defects, making debugging difficult.

Topic 10: Structs vs Classes
- Question: What is the core difference between a struct (value type) and a class (reference type) in C# memory management?
- Key Concepts: Structs on stack (copied by value); classes on heap (managed by garbage collector).
- Model Answer: A struct is a value type allocated on the stack that is copied by value whenever it is passed or assigned. A class is a reference type allocated on the heap whose memory is managed by the Garbage Collector, and assigning a class variable simply copies a reference pointing to the existing object.

[TIER 3 — ADVANCED]

Topic 11: OOP — Classes, Inheritance, Interfaces
- Question: What is an interface in C#, and how does implementing an interface differ from inheriting a class?
- Key Concepts: Interface defines contract of method signatures; classes can implement multiple interfaces.
- Model Answer: An interface defines a contract of method and property signatures without providing implementation details. A class can inherit from only one base class in C#, but it can implement multiple interfaces (e.g. class Player : Entity, IDamageable, IMovable), allowing polymorphism and flexible architecture across unrelated types.

Topic 12: Properties & Encapsulation
- Question: Why do C# developers use properties with { get; set; } instead of making class fields public?
- Key Concepts: Encapsulation; access control; validation logic can be added without breaking API.
- Model Answer: Properties encapsulate private fields by exposing controlled getter and setter accessors. This allows classes to validate incoming values (e.g. ensuring age is positive), restrict write access with private set, and maintain a stable public API that can be modified internally without breaking consuming code.

Topic 13: Delegates & Events
- Question: What is a delegate in C#, and how do events provide a safe way for objects to broadcast notifications?
- Key Concepts: Delegate is type-safe function pointer; events restrict invocation to declaring class.
- Model Answer: A delegate is a type-safe function pointer that holds references to methods with matching signatures. An event wraps a delegate to provide a publish-subscribe model, allowing external classes to subscribe (+-) or unsubscribe (-=), but restricting invocation strictly to the class that owns the event, preventing outside code from resetting or firing it.

Topic 14: LINQ
- Question: What do the LINQ methods .Where() and .Select() do when querying a collection of items in C#?
- Key Concepts: .Where() filters items; .Select() projects/transforms items; deferred execution.
- Model Answer: .Where() filters a collection based on a boolean predicate, retaining only the items that meet the condition (like finding players with health > 0). .Select() projects and transforms each item into a new form (like extracting just the usernames from a list of user objects).

Topic 15: Generics
- Question: Why are C# Generics (<T>) better for performance and safety than using general object types and casting?
- Key Concepts: Type safety at compile time; eliminates boxing/unboxing overhead for value types.
- Model Answer: Generics allow classes and methods to operate on specified placeholder types (<T>) without losing type safety at compile time. This avoids runtime casting exceptions and eliminates boxing and unboxing performance overhead when storing value types like integers.

Topic 16: File I/O
- Question: How does File.ReadAllText() simplify reading a file in C#, and why should stream resources be wrapped in a using statement?
- Key Concepts: File helper for quick reads; using statement ensures deterministic IDisposable cleanup.
- Model Answer: File.ReadAllText() simplifies I/O by opening, reading the entire file content into a string, and closing the file stream in a single convenient call. For ongoing streams (like FileStream or StreamReader), wrapping them in a "using" statement guarantees that Dispose() is called immediately when done, releasing unmanaged file locks even if an exception occurs.

WORLD 3: C++

[TIER 1 — FOUNDATIONS]

Topic 1: Variables & Data Types
- Question: What is the difference between an int, a float, and a char in C++, and why does C++ require declaring types upfront?
- Key Concepts: Memory allocation; int for whole numbers, float for decimals, char for single characters.
- Model Answer: In C++, an int stores whole numbers (usually 4 bytes), a float stores fractional decimal numbers, and a char stores a single ASCII character (1 byte). C++ requires explicit type declarations upfront so the compiler knows exactly how many bytes of memory to reserve and can generate fast, optimized machine code.

Topic 2: Operators
- Question: What is the difference between prefix increment (++x) and postfix increment (x++) in C++?
- Key Concepts: Prefix increments before expression evaluation; postfix increments after evaluation.
- Model Answer: The prefix operator (++x) increments the variable's value first and then returns the newly incremented value to the surrounding expression. The postfix operator (x++) returns the original value to the expression first, and then increments the variable afterward.

Topic 3: I/O (cin / cout)
- Question: How do std::cin and std::cout use the stream operators >> and << to read and write data in C++?
- Key Concepts: Streams in <iostream>; << insertion operator; >> extraction operator.
- Model Answer: std::cout represents the standard output stream, and uses the insertion operator (<<) to send formatted text and variables to the console (e.g. std::cout << "Score: " << score;). std::cin represents the standard input stream, and uses the extraction operator (>>) to extract data from keyboard input into a target variable (e.g. std::cin >> score;).

Topic 4: Conditional Statements
- Question: How does the ternary conditional operator (condition ? expr1 : expr2) provide a shorthand for if-else in C++?
- Key Concepts: Inline expression returning value; condition evaluated; concise variable assignment.
- Model Answer: The ternary operator evaluates a boolean condition: if the condition is true, it evaluates and returns expr1; if false, it returns expr2. This allows you to assign a variable conditionally in a single concise line (e.g. int max = (a > b) ? a : b;) instead of writing a four-line if-else block.

Topic 5: Loops
- Question: What is the key difference between a while loop and a do-while loop in C++?
- Key Concepts: while checks condition before iteration; do-while checks condition after, guaranteeing at least one run.
- Model Answer: A while loop checks its condition at the beginning before executing the loop body; if the condition is false initially, the body never runs. A do-while loop checks its condition at the end, guaranteeing that the code block executes at least once regardless of whether the condition is true or false.

[TIER 2 — CORE]

Topic 6: Functions & Function Overloading
- Question: What is function overloading in C++, and how does the compiler know which overloaded version to call?
- Key Concepts: Same function name with different parameter signatures; signature matching at compile time.
- Model Answer: Function overloading allows multiple functions to share the exact same name as long as their parameter lists differ in number, types, or order. The C++ compiler inspects the argument types passed at the call site and matches them to the corresponding function signature at compile time.

Topic 7: Arrays & Strings
- Question: Why is std::string generally preferred over raw C-style null-terminated char arrays in modern C++?
- Key Concepts: std::string handles dynamic sizing, memory safety, and boundary checks; prevents buffer overflows.
- Model Answer: Raw C-style strings are fixed character arrays that require manual memory tracking and a trailing null terminator ('\0'), which frequently leads to buffer overflow vulnerabilities. std::string manages its own memory dynamically, provides convenient methods (like .length(), concatenation with +, and comparisons with ==), and prevents memory corruption.

Topic 8: Pointers & References
- Question: What is the difference between a pointer (*) and a reference (&) in C++, and can a reference be reassigned?
- Key Concepts: Pointer stores address and can be null/reassigned; reference is alias bound at initialization.
- Model Answer: A pointer is a variable that stores a memory address; it can be set to nullptr and reassigned to point to different variables over its lifetime. A reference is an alias for an existing variable that must be initialized upon declaration and cannot be reassigned to refer to another variable afterward.

Topic 9: Structures
- Question: How do you define a struct in C++, and how do you access its members using dot notation versus pointer arrow notation (->)?
- Key Concepts: struct bundles members (default public); dot (.) on object; arrow (->) on pointer.
- Model Answer: You define a struct using struct Name { int x; int y; };. When working directly with a struct object, you access members using dot notation (point.x). When working with a pointer to a struct, you access members using the arrow operator (ptr->x), which dereferences the pointer and accesses the member in one step.

Topic 10: Dynamic Memory (new / delete)
- Question: What happens if memory allocated with "new" in C++ is never freed with "delete"? What is this issue called?
- Key Concepts: Manual heap management; memory leak consumes system RAM until crash.
- Model Answer: If memory allocated on the heap using "new" is never deallocated with "delete", that memory remains reserved by the program even after pointers to it go out of scope. This is called a "memory leak," which gradually consumes system RAM and can eventually cause the operating system or application to crash.

[TIER 3 — ADVANCED]

Topic 11: OOP — Constructors, Destructors, Inheritance
- Question: When is a destructor called in C++, and why are destructors essential for cleaning up resources?
- Key Concepts: ~ClassName(); called on object destruction/scope exit; releases heap memory and file handles.
- Model Answer: A destructor (prefixed with ~) is automatically called when an object goes out of scope or is explicitly deleted. Destructors are essential under the RAII (Resource Acquisition Is Initialization) pattern because they ensure that unmanaged resources—such as dynamically allocated heap memory, open files, or network sockets—are guaranteed to be released cleanly.

Topic 12: Polymorphism & Virtual Functions
- Question: What is the purpose of the "virtual" keyword in a C++ base class method, and what happens if it is omitted?
- Key Concepts: Dynamic dispatch; vtable lookup; calling overridden method through base pointer.
- Model Answer: Marking a base class method with "virtual" enables dynamic dispatch, ensuring that when a method is called through a base class pointer or reference, the program executes the derived class's overridden version at runtime. If omitted, the compiler binds the call statically at compile time, invoking the base class version instead.

Topic 13: Templates
- Question: How does a template function (template <typename T>) allow you to write one function that works for ints, floats, and strings?
- Key Concepts: Generic programming; compiler generates concrete functions for each instantiated type.
- Model Answer: A template function defines a generic blueprint where T acts as a type placeholder. During compilation, whenever you call the function with a specific type (like an int or a string), the C++ compiler automatically generates a concrete version of the function customized for that specific data type, eliminating duplicate code without sacrificing performance.

Topic 14: STL (vectors, maps, iterators)
- Question: What is std::vector in C++, and why is vector::push_back() more flexible than a traditional fixed array?
- Key Concepts: Dynamic array; contiguous memory; push_back appends and resizes automatically.
- Model Answer: std::vector is an STL container that acts as a dynamically resizable array stored in contiguous memory. Using vector.push_back() is far more flexible than a fixed array because it automatically allocates additional memory and expands its capacity as new elements are added, freeing the programmer from manual memory management.

Topic 15: Exception Handling
- Question: How do the throw, try, and catch keywords work together to handle unexpected runtime errors in C++?
- Key Concepts: throw signals an error; try wraps risky code; catch intercepts and recovers from the exception.
- Model Answer: When code detects a runtime error it cannot handle locally, it uses "throw" to emit an exception object. The code is enclosed in a "try" block, which monitors execution; if an exception is thrown, normal execution halts, stack unwinding occurs, and control transfers to the matching "catch" block to handle the error cleanly.

Topic 16: File Handling
- Question: How do std::ifstream and std::ofstream open and close files for reading and writing in C++?
- Key Concepts: <fstream>; ifstream for input reading; ofstream for output writing; auto-close via destructor.
- Model Answer: std::ifstream creates an input file stream to open and read data from a file, while std::ofstream creates an output file stream to open, create, or overwrite a file for writing. Both classes automatically close their underlying file handles when the stream objects go out of scope due to their RAII destructors.

WORLD 4: HTML

[TIER 1 — FOUNDATIONS]

Topic 1: Document Structure & Tags
- Question: What is the purpose of the <!DOCTYPE html> declaration at the very top of an HTML document?
- Key Concepts: Informs browser of HTML5 standard; prevents quirks mode rendering.
- Model Answer: The <!DOCTYPE html> declaration informs the browser that the document is written in modern HTML5. This ensures that the web browser parses and renders the page in standard mode rather than legacy "quirks mode," guaranteeing consistent layout across different browsers.

Topic 2: Headings & Text Formatting
- Question: Why should a webpage generally only have one <h1> element, and how does heading hierarchy help accessibility?
- Key Concepts: Single primary heading; hierarchical outline <h1> down to <h6>; screen reader navigation.
- Model Answer: A webpage should generally have only one <h1> element because it represents the primary topic or title of the page. Maintaining a clean heading hierarchy (from <h1> down to <h6> without skipping levels) allows screen readers and search engines to construct an accurate structural outline, enabling visually impaired users to navigate sections easily.

Topic 3: Lists
- Question: What is the difference between an ordered list (<ol>) and an unordered list (<ul>) in HTML?
- Key Concepts: <ol> uses numbers for sequence; <ul> uses bullets for non-sequential items.
- Model Answer: An ordered list (<ol>) formats list items (<li>) with sequential numbers or letters, indicating that the sequence or step-by-step order matters (like a recipe or ranking). An unordered list (<ul>) displays items with bullet points, indicating that the order of items is arbitrary.

Topic 4: Links & Images
- Question: Why is the "alt" attribute on an <img> tag essential, and what does the "href" attribute do on an <a> tag?
- Key Concepts: alt provides screen reader description and fallback text; href specifies hyperlink destination.
- Model Answer: The "alt" attribute on an <img> tag provides alternative text for screen readers so visually impaired users know what the image depicts, and displays fallback text if the image fails to load. The "href" attribute on an anchor tag (<a>) specifies the target URL destination that the browser navigates to when clicked.

Topic 5: Tables
- Question: What is the difference between a table header cell (<th>) and a regular table data cell (<td>) in HTML?
- Key Concepts: <th> denotes header (bold, centered, screen reader accessible); <td> holds tabular data.
- Model Answer: A <th> element denotes a header cell that labels a row or column, and is typically bolded and centered by default while providing semantic meaning for assistive technologies. A <td> element denotes a standard data cell containing the actual values or content of the table.

[TIER 2 — CORE]

Topic 6: Forms & Input Elements
- Question: How does the "type" attribute on an <input> element change how it behaves (for example, text vs checkbox vs submit)?
- Key Concepts: Dictates UI presentation; validation behavior; mobile keyboard layouts.
- Model Answer: The "type" attribute instructs the browser what kind of data the input accepts and how to render it. For instance, type="text" renders a single-line text field, type="checkbox" renders a toggleable check square, and type="submit" renders a button that submits the parent form. It also triggers mobile keyboards tailored for numbers, emails, or URLs.

Topic 7: Semantic HTML5 Elements
- Question: Why is using semantic elements like <header>, <main>, and <nav> better than wrapping everything inside generic <div> tags?
- Key Concepts: Semantic meaning; accessibility landmarks; SEO benefits; code readability.
- Model Answer: Semantic elements clearly describe their meaning and purpose to both the browser and developers. Assistive technologies (like screen readers) use landmarks such as <nav> and <main> to allow users to skip directly to key areas, and search engines use them to index content accurately, which generic <div> tags cannot provide.

Topic 8: Div/Span & Layout Structure
- Question: What is the difference between a block-level element like <div> and an inline element like <span>?
- Key Concepts: Block starts on new line and takes full width; inline flows within text taking only needed space.
- Model Answer: A block-level element like <div> starts on a new line and expands to fill the full available width of its parent container, making it ideal for structural layout. An inline element like <span> does not start on a new line and only occupies as much width as its content, allowing you to style specific words or phrases inside a paragraph.

Topic 9: Multimedia (audio/video)
- Question: What does the "controls" attribute do when added to an HTML5 <video> tag?
- Key Concepts: Native browser playback controls (play, pause, volume, scrubber).
- Model Answer: Adding the boolean "controls" attribute instructs the browser to display its built-in multimedia interface, giving the user access to essential video controls including play/pause buttons, a progress scrubber bar, volume sliders, and a full-screen toggle.

Topic 10: Meta Tags & SEO Basics
- Question: Why is the <meta name="viewport" content="..."> tag essential for building mobile-friendly websites?
- Key Concepts: Responsive viewport scaling; prevents default desktop zoom out on phones.
- Model Answer: Without the viewport meta tag, mobile browsers assume the page is designed for desktop screens and render it zoomed far out at a wide viewport. Setting content="width=device-width, initial-scale=1.0" tells the browser to match the page width to the device screen and set the initial zoom level to 1:1, making responsive CSS work properly.

[TIER 3 — ADVANCED]

Topic 11: Accessibility (ARIA basics)
- Question: What is the purpose of ARIA attributes (like aria-label and role) in HTML, and when should they be used?
- Key Concepts: Accessible Rich Internet Applications; supplements HTML semantics when native elements cannot.
- Model Answer: ARIA attributes provide descriptive metadata for assistive devices when standard HTML elements cannot convey the full role, state, or label of a custom interactive widget (e.g. adding aria-label="Close menu" to an icon button). They should only be used when native semantic HTML elements are insufficient.

Topic 12: Form Validation Attributes
- Question: How does the HTML "required" attribute prevent a form from submitting invalid data without using JavaScript?
- Key Concepts: Native browser form validation; submission blocked if field is blank; warning tooltip displayed.
- Model Answer: The "required" attribute activates browser-level client-side form validation. When a user attempts to submit a form while a required input is empty, the browser automatically blocks the submission event, highlights the invalid field, and displays a localized warning tooltip prompting the user to fill it in.

Topic 13: Embedding & iframes
- Question: What is an <iframe> used for in HTML, and why is the "sandbox" attribute recommended for security?
- Key Concepts: Inline frame embeds external web page; sandbox isolates content and restricts scripts.
- Model Answer: An <iframe> (inline frame) embeds another separate HTML document or third-party widget (like a map or video) inside the current webpage. The "sandbox" attribute is recommended because it restricts the embedded page from running malicious scripts, opening popups, or accessing parent cookies unless specific permissions are explicitly granted.

Topic 14: HTML5 APIs Overview (Canvas, LocalStorage)
- Question: What is the difference between drawing pixels on an HTML <canvas> and storing data in browser localStorage?
- Key Concepts: Canvas is visual bitmap drawing surface; localStorage is persistent key-value text storage.
- Model Answer: The <canvas> element is a scriptable drawing surface that allows JavaScript to render 2D bitmap graphics, animations, and game visuals pixel by pixel. In contrast, localStorage is a client-side web storage API that saves text-based key-value data persistently in the browser across sessions without touching the display.

WORLD 5: CSS
================================================================================

[TIER 1 — FOUNDATIONS]

Topic 1: Selectors & Specificity
- Question: Which selector has higher specificity in CSS: an ID selector (#hero) or a class selector (.hero), and why?
- Key Concepts: Specificity hierarchy: inline > ID > class/attribute/pseudo-class > element.
- Model Answer: An ID selector (#hero) has significantly higher specificity than a class selector (.hero) because CSS specificity ranks IDs above classes in its hierarchy (a single ID overrides hundreds of classes). If an element has styles applied by both an ID and a class selector, the ID styles take precedence.

Topic 2: The Box Model
- Question: What are the four components of the CSS Box Model, and how does box-sizing: border-box affect element width?
- Key Concepts: Content, padding, border, margin; border-box includes padding/border inside width.
- Model Answer: The CSS Box Model consists of content at the core, surrounded by padding, then a border, and outer margin. By default (content-box), adding padding or borders increases the total rendered width of the element. Setting box-sizing: border-box includes padding and borders within the declared width, preventing elements from unexpectedly overflowing containers.

Topic 3: Colors & Units
- Question: What is the difference between pixels (px) and rem units in CSS, and why are rem units preferred for typography?
- Key Concepts: px is absolute; rem is relative to root font size; rem respects user accessibility settings.
- Model Answer: Pixels (px) are absolute units that do not scale when a user changes their browser's default font size. Rem units are relative to the root (<html>) font size (typically 16px). Rem units are preferred for typography because they automatically scale when users adjust browser text settings for accessibility.

Topic 4: Typography
- Question: How do font-family, font-size, and line-height work together to make text readable on a webpage?
- Key Concepts: font-family defines typeface; font-size controls scale; line-height sets vertical line breathing room.
- Model Answer: font-family selects the typeface and fallback fonts; font-size establishes the visual scale and hierarchy of headings and body copy; line-height (usually 1.5 to 1.6 for body text) provides vertical spacing between text lines to prevent crowding and ensure comfortable readability.

Topic 5: Backgrounds & Borders
- Question: How does border-radius round the corners of an element, and how do you make a square element completely circular?
- Key Concepts: border-radius curves corners; 50% on square creates perfect circle.
- Model Answer: The border-radius property rounds the corners of an element's outer border edge using radius measurements. To make an element completely circular, the element must have equal width and height (a square), and border-radius must be set to 50%.

[TIER 2 — CORE]

Topic 6: Flexbox
- Question: What is the difference between justify-content (main axis) and align-items (cross axis) in CSS Flexbox?
- Key Concepts: Flex container axes; justify-content along primary direction; align-items perpendicular.
- Model Answer: In Flexbox, justify-content controls how flex items are distributed and aligned along the main axis (horizontally by default when flex-direction: row). align-items controls how flex items are aligned along the cross axis (perpendicular to the main axis, vertically by default).

Topic 7: Grid Layout
- Question: When would you choose CSS Grid over CSS Flexbox to lay out components on a page?
- Key Concepts: Flexbox is 1D (row or column); Grid is 2D (rows and columns simultaneously).
- Model Answer: You choose CSS Grid when designing two-dimensional layouts where you need to align elements along both rows and columns simultaneously (like photo galleries, dashboards, or full page skeletons). You choose Flexbox for one-dimensional layouts where items flow along a single axis (like navigation bars or button groups).

Topic 8: Positioning (relative / absolute / fixed)
- Question: What is the difference between position: relative, position: absolute, and position: fixed in CSS?
- Key Concepts: relative offsets from normal flow; absolute positions relative to ancestor; fixed anchors to viewport.
- Model Answer: position: relative keeps an element in document flow while allowing positional offsets (top, left) and creating a coordinate context for child elements. position: absolute removes the element from document flow and positions it relative to its nearest positioned ancestor. position: fixed removes the element and anchors it relative to the browser viewport so it stays in place during scrolling.

Topic 9: Responsive Design & Media Queries
- Question: How does a CSS @media query with (max-width: 768px) allow a website to change its layout on mobile phones?
- Key Concepts: Conditional CSS blocks based on device characteristics; responsive reflow.
- Model Answer: An @media (max-width: 768px) query creates a conditional block of CSS rules that the browser only applies when the viewport width is 768 pixels or narrower. This allows developers to adjust multi-column desktop layouts to single-column mobile layouts and adjust font sizes for smaller screens.

Topic 10: Pseudo-classes & Pseudo-elements
- Question: What is the difference between a pseudo-class like :hover and a pseudo-element like ::before in CSS?
- Key Concepts: Pseudo-class (:state) targets element state; pseudo-element (::part) creates virtual sub-elements.
- Model Answer: A pseudo-class (single colon, like :hover or :focus) targets an existing element when it enters a specific state, such as when a user hovers a mouse over it. A pseudo-element (double colon, like ::before or ::after) generates a virtual element that you can insert and style within an existing element without adding extra HTML.

[TIER 3 — ADVANCED]

Topic 11: CSS Variables (Custom Properties)
- Question: Why are CSS Variables (--my-color) declared in :root, and how do you use the var() function to apply them?
- Key Concepts: Global scope in :root; var(--name) retrieval; dynamic reusability and theming.
- Model Answer: Declaring CSS Variables in the :root pseudo-class gives them global scope, making them accessible to every element throughout the stylesheet. You apply them using the var() function (e.g. background-color: var(--accent-gold);), which makes sitewide color changes and dark/light themes easy to maintain.

Topic 12: Animations & Transitions
- Question: What is the difference between a simple CSS transition and a multi-step @keyframes animation?
- Key Concepts: Transitions interpolate between two states on trigger; @keyframes defines multi-step self-running timeline.
- Model Answer: A transition smoothly interpolates property changes between two states when triggered by an event (like a :hover change). An @keyframes animation defines a multi-step timeline using percentage stops (like 0%, 50%, 100%) that can run automatically, loop indefinitely, and change complex properties without requiring user interaction.

Topic 13: Transform
- Question: Why is transform: translateY(-5px) better for animation performance than changing the top or margin property?
- Key Concepts: GPU hardware acceleration; composite-only rendering; avoids layout reflow and repaint.
- Model Answer: Changing properties like top or margin forces the browser to recalculate layout geometry and repaint the document, which causes stuttering (jank). The transform property is handled by the GPU on the compositor thread without triggering layout reflow, resulting in silky-smooth 60fps animations.

Topic 14: CSS Architecture Basics (BEM naming)
- Question: What do the Block, Element, and Modifier stand for in the BEM CSS naming convention, and why is it useful?
- Key Concepts: BEM syntax: block__element--modifier; prevents selector collisions; promotes component reuse.
- Model Answer: In BEM, Block represents a standalone component (e.g. .card), Element represents a child part bound to that block (.card__title), and Modifier represents a state or variation flag (.card--featured). BEM is useful because it keeps selector specificity low and flat while preventing style collisions in large projects.

WORLD 6: JAVASCRIPT
================================================================================

[TIER 1 — FOUNDATIONS]

Topic 1: Variables (var / let / const)
- Question: What is the difference between "let" and "const" in JavaScript, and why should you avoid using "var"?
- Key Concepts: let allows reassignment; const prevents reassignment; both are block-scoped; var has function-scope issues.
- Model Answer: "let" allows you to reassign new values later, whereas "const" prevents reassignment after declaration. Both are block-scoped. You should avoid "var" because it is function-scoped and hoisted with undefined, which frequently causes scope leakage and accidental bugs.

Topic 2: Data Types & Operators
- Question: What is the difference between null and undefined in JavaScript?
- Key Concepts: undefined means declared but not assigned; null is an intentional assignment of empty value.
- Model Answer: "undefined" means a variable has been declared but has not yet been assigned any value (or a function didn't return a value). "null" is an intentional assignment representing the deliberate absence of any object or value.

Topic 3: Conditionals
- Question: What is the difference between == (loose equality) and === (strict equality) in JavaScript?
- Key Concepts: == converts types (type coercion); === checks value and type without converting.
- Model Answer: Loose equality (==) attempts to convert the operands to the same type before comparing, meaning '5' == 5 evaluates to true. Strict equality (===) compares both value and data type without any type conversion, meaning '5' === 5 evaluates to false. === is recommended to prevent unexpected bugs.

Topic 4: Loops
- Question: How does a for...of loop simplify iterating over the elements of an array compared to a traditional for loop?
- Key Concepts: for...of accesses values directly; eliminates index counter and length management.
- Model Answer: A for...of loop iterates directly over the values of an iterable collection (like const item of array) without requiring index variables, length lookups, or manual incrementing, making the code much cleaner and avoiding off-by-one errors.

Topic 5: Functions
- Question: What is the difference between a function parameter and an argument in JavaScript?
- Key Concepts: Parameter is placeholder in definition; argument is concrete value passed on invocation.
- Model Answer: A parameter is the named placeholder variable defined in the function declaration (e.g. x in function square(x)). An argument is the actual value or expression passed into the function when it is called (e.g. 5 in square(5)).

[TIER 2 — CORE]

Topic 6: Arrays & Array Methods
- Question: What is the difference between the .map() method and the .filter() method on a JavaScript array?
- Key Concepts: .map() transforms every element; .filter() selects elements matching a boolean condition.
- Model Answer: The .map() method iterates through every element, runs a transformation function, and returns a new array of the exact same length containing transformed values. The .filter() method tests each element against a boolean condition and returns a new array containing only the elements that passed the test.

Topic 7: Objects
- Question: When must you access an object property using bracket notation obj[key] instead of dot notation obj.key?
- Key Concepts: Dynamic property names stored in variables; keys containing spaces, dashes, or starting with numbers.
- Model Answer: You must use bracket notation (obj[key]) when the property name is stored inside a variable, contains spaces, hyphens, or begins with a number. Dot notation (obj.key) can only be used with valid, static identifier names known at code writing time.

Topic 8: DOM Manipulation
- Question: How do you select an element with document.querySelector() and change its text content in JavaScript?
- Key Concepts: CSS selector syntax; .textContent property updates rendered text safely.
- Model Answer: You pass a CSS selector string to document.querySelector(selector) to find the first matching element on the page (e.g. const title = document.querySelector('#title')). Once selected, you change its text by assigning a new string to its .textContent property (title.textContent = 'New Heading').

Topic 9: Events
- Question: Why is element.addEventListener("click", fn) preferred over inline HTML onclick attributes?
- Key Concepts: Separation of concerns; allows multiple listeners on same element; clean removal with removeEventListener.
- Model Answer: addEventListener is preferred because it keeps JavaScript logic completely separated from HTML structure, allows you to attach multiple independent listeners to the same event on an element, and provides options for event bubbling/capturing and clean listener removal.

Topic 10: ES6+ Syntax (arrow functions, template literals, destructuring)
- Question: How does object destructuring (const { name, age } = user) simplify extracting values from an object?
- Key Concepts: Unpacks properties into variables with matching names; concise and readable.
- Model Answer: Object destructuring allows you to unpack multiple properties from an object directly into distinct local variables in a single clean line (const { name, age } = user;), eliminating the need to write repetitive assignment statements like const name = user.name; const age = user.age;.

[TIER 3 — ADVANCED]

Topic 11: Asynchronous JS (Callbacks, Promises, async/await)
- Question: Why do we use async and await instead of running synchronous code when loading data from a server?
- Key Concepts: Single-threaded event loop; network latency; async/await prevents browser UI freeze.
- Model Answer: JavaScript runs on a single main thread. If network requests were synchronous, the entire browser tab would completely freeze and become unresponsive while waiting for the server to reply. Using async/await pauses execution of that specific function non-blockingly while allowing the browser to keep rendering and handling user clicks.

Topic 12: Fetch API / Axios
- Question: What does the fetch() function return, and why do you have to call response.json() before using the data?
- Key Concepts: Returns Promise resolving to Response stream; response.json() reads stream and parses JSON.
- Model Answer: The fetch() function returns a Promise that resolves to a Response object representing the HTTP headers and stream. Because the response body arrives as a raw data stream, you must call and await response.json() to read the stream to completion and parse it into a JavaScript object.

Topic 13: Error Handling (try/catch)
- Question: How does wrapping risky code in a try...catch block prevent an entire web application from crashing?
- Key Concepts: Intercepts unhandled exceptions; transfers control to catch block; allows graceful degradation.
- Model Answer: When an unexpected runtime error occurs inside a try block, JavaScript halts execution of that block and immediately transfers control to the catch block rather than throwing an unhandled exception to the browser. This allows the application to show an error message and continue running safely.

Topic 14: Closures & Scope
- Question: What is a closure in JavaScript, and how does an inner function retain access to variables from its outer function?
- Key Concepts: Lexical scoping; inner function references outer lexical environment even after outer returns.
- Model Answer: A closure is the combination of a function bundled together with references to its surrounding lexical environment. When an inner function references variables from its enclosing outer function, JavaScript preserves that environment in memory, allowing the inner function to access those variables even after the outer function has finished executing.

Topic 15: JSON Handling
- Question: What is the difference between JSON.stringify() and JSON.parse() when working with JavaScript objects?
- Key Concepts: JSON.stringify converts JS object to JSON string; JSON.parse converts JSON string back into JS object.
- Model Answer: JSON.stringify() takes a JavaScript object or array and serializes it into a formatted JSON text string for storage or network transmission. JSON.parse() takes a valid JSON text string and deserializes it back into a native JavaScript object or array in memory.

Topic 16: Modules (import/export)
- Question: What is the difference between a named export and a default export when using JavaScript ES modules?
- Key Concepts: Named export can have multiple per file with exact names; default export has single primary export per file.
- Model Answer: A file can have multiple named exports (export const a = 1;), which must be imported using exact matching names inside curly braces (import { a } from './file.js'). A file can have only one default export (export default function), which can be imported without curly braces using any arbitrary identifier name.
